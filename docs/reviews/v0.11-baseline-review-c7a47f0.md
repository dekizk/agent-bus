## Strengths — the hardest things done right

### 1. Pause acknowledgement derives from log position, not observation time

`projection.py:140–143`: `pause_assignment_snapshot` captures the active assignment set when the pause request *enters the ordered log*. The acknowledgement names that immutable snapshot regardless of which stronger task control (cancel, task-pause, supersession, deadline) wins before publication. The idempotency key stays deterministic because the payload is a function of log position.

The reviewer had proposed revision-suffixed keys; this is cleaner. `test_workflow_pause_ack_snapshot_tolerates_stronger_task_transitions` covers all four competing transitions in the publication window.

### 2. Budget accounting distinguishes reservation from settlement

`projection.py:178–190`: `charged_tokens()` / `charged_cost_usd()` return `max(reserved, reported)` while the assignment is active or any usage report is missing, and `reported` only after a clean end. Wall-clock budgets derive from `workflow_first_created_at` (log), not a timer. `workflow_budget_usage` surfaces `missing_token_reports` / `missing_cost_reports` so operators can see *why* a budget reads as conservative.

### 3. Policy model enforces the defaults-materialization rule as a contract

`workflow.policy_set` with `source: default | operator`; `default` must be PM-emitted, `operator` must not be (`bus.py`, validate_event). Policy targets must be existing workflows (same rule as pause/resume). `test_later_policy_decrease_does_not_retroactively_reject_assignment` pins that policy changes govern future admission, not accepted history.

### 4. Snapshots are disposable, fingerprinted by loaded code, and race-pinned

`projection_store.py:31–40`: `reducer_fingerprint()` hashes *loaded bytecode* of the reducer modules, not source files, so editing a checkout under a running PM cannot mislabel old state. Snapshots are checksummed, size-capped (64 MiB), fall back to full replay on any mismatch, and the docstring forbids deserializing executable code. `test_replay_is_pinned_when_a_publisher_appends_during_read` closes the snapshot/suffix boundary race via a pinned SQLite read transaction.

### 5. Release gates verify the installed artifact, not the checkout

`scripts/check_release.py` builds a wheel, installs it in a fresh venv, asserts every module resolves from inside that prefix (catching the editable-install shadowing class that bit the diff-review consumer project), checks license metadata, and runs a demo. `tests/fixtures/compatibility/v0.11.0-upgrade/` pins a database plus expected projection so future reducers cannot silently reinterpret history. Recovery tests fail closed on tampered artifacts, symlinked hash directories, and interrupted copies.

## Observations (non-blocking)

1. **Module size.** `projection.py` is 1,792 lines and `bus.py` 2,025. Both remain coherent, but the projection now carries tasks, workflows, agent policies, accounting, and the scheduling cursor. When next touched, consider splitting accounting records and budget methods into their own module; `reducer_fingerprint()` already hashes a module list, so it is a natural seam.
2. **Partial usage reports.** `charged_tokens` treats any `None` in a multi-invocation record as "missing" and keeps the full reserve. With three reported and one missing invocation, the charge is `max(reserve, reported_3)` rather than `reported_3 + reserve_share`. Safe for v1; document the rule so operators aren't surprised.
3. **`reconcile(..., cursor=None)` optimistic path** still exists. Confirm `main()` cannot reach it; if test-only, add an assertion or deprecation comment to prevent regression to the pre-hardening behavior.
4. **Housekeeping.** Root `MULTI_AGENT_REVIEW_SUMMARY.md` is stale (every finding fixed). Move under `docs/reviews/` or delete.
